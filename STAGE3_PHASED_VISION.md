## 0. РАЗЛИЧЕНИЕ (то, ради чего владелец сказал «с различением»)

**Северная звезда:** агент-управляемое будущее — платформенный бизнес и операторские роли, выполняемые
ИИ-агентами; владелец — визионер и создатель. ZooLink = ПЕРВАЯ площадка, которую делаем агент-управляемой.

**Главный блокер — ВРЕМЕННОЙ, и он НЕ на линии кода.** Различение, которое всё определяет:

| | Линия ФУНКЦИОНАЛА (L-ФУНК) | Линия ВЫХОДА К ЛЮДЯМ (L-ВРЕМЯ) |
|---|---|---|
| Что закрывает | код · схема · тесты · надёжность · производительность | продакшн · публичный доступ · реклама · приём денег · сбор ПД живых людей |
| Чем гейтится | ИНЖЕНЕРНО — нашими 13 осями | ЮРИДИЧЕСКИ + КАЛЕНДАРНО — ФЗ-152, оферта, 54-ФЗ, ветеринария, регулятор, чужая подпись |
| Скорость | недели разработки, УСКОРЯЕТСЯ трудом/агентами | месяцы КАЛЕНДАРЯ, разработкой НЕ сокращается |
| Финиш | раньше | позже — И ЭТО ПЛАНИРУЕТСЯ, не провал |

**Вывод-стратегия (почему «пилить реализацию»):** L-ВРЕМЯ — ДЛИННЫЙ ПОЛЮС. Значит (а) L-ВРЕМЯ запускаем
СЕЙЧАС и параллельно (она тикает по календарю, чем раньше начата — тем раньше финиш), а (б) L-ФУНК
**пилим вперёд до упора с выключённым рубильником** — чтобы к моменту, когда L-ВРЕМЯ дозреет (месяцы),
продукт был функционально готов и оставалось только щёлкнуть рубильники. Репутация уже в спящей форме,
agent-auth за toggle — рамка не новая, мы так уже умеем; этап 3 делает её ЯВНОЙ и полной.

**Различение помощника (восприятие мира, m-20260805-004441; его факты = гипотезы, перспектива — вход):**
*«Ускорилось всё, что стало API; НЕ ускоряется всё, где риск лежит на ЧУЖОЙ стороне»* — банк, регулятор,
контрагент проверяют своим календарём, деньги/технология его почти не сжимают. Это и есть точная граница
L-ВРЕМЯ. Два следствия, которые меняют план:
- **L-ВРЕМЯ — не только блокер, но и РОВ.** Конкуренты под тем же стимулом «код готов, запустимся грязно»
  горят на первом же конфликте; игрок, оформившийся медленно, но ЧИСТО, получает **календарное преимущество
  доверия — то, что не покупается деньгами**. Это довод ЗА параллельную временную линию, а не просто страховка.
- **Рубильник обязан иметь ЗАМОК.** «Код вперёд с выключённым рубильником» верно ровно пока рубильник нельзя
  щёлкнуть «на минутку» с живыми людьми. Замок = чек-лист правовой готовности (наш гейт продакшена ADR-0014,
  тот же принцип). В нише животных первый конфликт (больное животное, возврат) эмоционален → скандал виральный,
  репутационный удар необратим БЫСТРЕЕ, чем оформляется любое соглашение. Правовой долг копим осознанно и
  помечаем — как техдолг.

**Что НЕ ждёт L-ВРЕМЯ:** ничего в L-ФУНК. Юридическое перестаёт быть строкой-«блокер разработки»; G1–G4
из legal-мемо гейтят ВКЛЮЧЕНИЕ репутации для живых людей — и только это.

## 1. ЛИНИЯ ФУНКЦИОНАЛА (L-ФУНК) — пилим вперёд, гейт инженерный, рубильник off

Порядок — по ЦЕНЕ ИЗМЕНЕНИЯ (дорожает от откладывания → вперёд), не по удобству.

### F0 · Репутационная реформа схемы (A-iii + B-ii + β + Р-9/Р-10) — В РАБОТЕ
- **Источник:** AUDIT5 развилки A/B (architect) + Р-9/Р-10 (reviewer-qa: гейты не защищают инварианты). Гейт-пас держателя получен.
- **Даёт:** append-only-конфликт (намерение в таблице фактов) решён ДО живых данных; гейты начинают защищать инварианты, а не самосогласованность.
- **Измеряется:** 2 коммита, каждый фикс КРАСНЕЕТ от своей мутации (M-1/M-3/M-4 + мета-гейт: констрейнт мимо реестра → RED); база 712u/405e держится; миграция ×2.
- **Сломается если НЕ сделать:** markSold-путь структурно непостроим (PENDING→CONFIRMED = заблокированный UPDATE); правка отзыва невозможна; удаление инварианта из схемы остаётся зелёным (Р-10) — чиним схему прибором, который её же пропустил.
- **Цена откладывания:** РАСТЁТ — сейчас формы спят (0 markSold-строк, transfer все CONFIRMED), после первой живой продажи = миграция по живым деньгам/репутации.
- **L-ВРЕМЯ-зависимость:** нет. Спящая форма, рубильник off.

### F1 · Пять живых деплой-блокеров (отдельные паки, другой класс — держатель)
Каждый ломается на РЕАЛЬНОМ пути, не «когда-нибудь». Все — код-only, L-ВРЕМЯ не гейтит.
- **F1a · base-path /api/v1 ≠ /v1** (C1, 3 лейна+оркестратор). Даёт: API достижим в проде. Измеряется: запрос через Caddy к НЕ-health-маршруту → 200 (сейчас 404, живёт только /health). Сломается: первый деплой = полный отказ API. Цена откладывания: постоянна, но это ВОРОТА любого выхода.
- **F1b · throttler один ковш** (Б1, backend+security). Даёт: пер-клиентские лимиты. Измеряется: N клиентов с разных IP — каждый своё ведро (сейчас регистрация 5/15мин на ВСЮ платформу). Сломается: 6-й пользователь за 15 мин ловит 429 в день выхода на 1000 DAU.
- **F1c · H4 seed не зеркалирован** (Ф-1, devops+оркестратор). Даёт: demand-петля жива на свежей установке. Измеряется: свежий schema+seed → 24/24 шаблона (сейчас 22). Сломается: петля возврата молча мертва на любом новом деплое.
- **F1d · /health/live 500 при Redis-down** (devops живьём). Даёт: liveness переживает моргание Redis. Измеряется: /health/live → 200 при мёртвом Redis (сейчас 500). Сломается: моргание Redis → рестарт-петля (Dockerfile HEALTHCHECK туда).
- **F1e · СЛОЙ СООБЩЕНИЙ** (ось 2, 5 лейнов — крупнейший кластер). Даёт: человек ЧИТАЕТ уведомления/отказы. Измеряется: уведомление рендерит кличку/название + человеческий текст причины (сейчас UUID+код); notification_logs.status отражает доставку (сейчас жёстко 'SENT' — журнал лжёт). Сломается: продукт НЕЛЬЗЯ показать человеку как готовый — «умеет уведомлять, не умеет сказать».

### F2 · Наблюдаемость · устойчивость · обратимость · накопление (оси 6/8/9/4 красные)
- **Источник:** devops (3 прогона) + backend Б3.
- **Даёт:** владелец УЗНАЁТ, что сломалось; откат ПРОВЕРЕН; ретенция ФЗ-152 исполняется; ничто не растёт без границ.
- **Измеряется:** доменная метрика эмитится + алерт срабатывает на смерть cron (сейчас 0 доменных, 0 алертинга при 24 обещанных); откат ВЫПОЛНЕН на throwaway (сейчас 0 down-миграций, restore восстанавливает ничего); ретенция-джоб прунит по срокам privacy-policy (сейчас 0 из обещанных).
- **Сломается если НЕ сделать:** тихие отказы невидимы (журнал лжёт SENT, cron мрут молча); ФЗ-152-стирание молча встаёт; прод односторонний (нельзя откатить); throttler/список уведомлений/refresh_tokens растут до отказа.
- **L-ВРЕМЯ-зависимость:** ретенция ФЗ-152 пересекается с L-ВРЕМЯ (сроки в privacy-policy), но код-часть — L-ФУНК.

### F3 · Агент-власть (ЯДРО СЕВЕРНОЙ ЗВЕЗДЫ) — последняя на L-ФУНК, потому что [NS]-блокер
- **Источник:** security [NS] — 5 фиксов до зажигания agent_service_auth (PoliciesGuard fail-closed для AGENT, HUMAN-only запись агент-ворот, отказ сессионных путей AGENT, секрет вон из Redis, status в обмене) + F1 least-privilege базовой роли.
- **Даёт:** агент может БЕЗОПАСНО держать операторские роли (модерация — референс) → первый шаг агент-управляемости.
- **Измеряется:** scope AGENT принуждается на ВСЕХ маршрутах (сейчас 1 из 83); NO-GO→GO гейт security; мутация «агент без scope на защищённый маршрут» → 403.
- **Сломается если НЕ сделать:** сама Северная звезда заблокирована — агент нельзя включить безопасно (PoliciesGuard fail-OPEN, AGENT-ADMIN флипает свой гейт).
- **L-ВРЕМЯ-зависимость:** ⚠️ ГЛУБОКАЯ — включение агента-оператора для ЖИВЫХ решений упирается в T6 (правосубъектность агента, ст.16/1253.1) — это не код, это мир не готов. Форму строим (L-ФУНК), включение — за T6.

## 2. ЛИНИЯ ВЫХОДА К ЛЮДЯМ (L-ВРЕМЯ) — ДЛИННЫЙ ПОЛЮС, запускать СЕЙЧАС параллельно

Здесь срок определяется НЕ трудом, а календарём и чужой подписью. Числа — из legal/finance-лейнов AUDIT5.
Это рёбра графа: F-этапы за рубильником ждут ИМЕННО эти.

### T0 · Юрлицо (ИП/ООО) — КОРЕНЬ всей L-ВРЕМЯ
- **Источник:** legal B1/ФЗ-129 + finance. **Ничто** юридическое/платёжное/РКН не крепится без ОГРН (все плейсхолдеры оферты, РКН-уведомление, касса).
- **Срок:** регламент ФНС **3 рабочих дня** (ст.8 ч.3 ФЗ-129) — но взносы ИП ≈4 750 ₽/мес ТИКАЮТ С ДАТЫ РЕГИСТРАЦИИ, не с выручки (finance).
- **Развилка (владельцу+legal):** КОГДА регистрировать. Раньше = раньше стартует вся L-ВРЕМЯ, но раньше тикают взносы (инфра спящего продукта = 742 ₽/мес, взносы ИП в 6× дороже). Рекомендация: регистрировать, когда L-ФУНК близка к «функционально готова» И оферта-черновик у counsel — чтобы 3-дневное юрлицо не простаивало под взносами.
- **Что сломается без T0:** вся L-ВРЕМЯ стоит; ни один F-рубильник наружу не щёлкнуть легально.

### T1 · Оферта · ToS · privacy · согласия — counsel-медленное
- **Источник:** legal (весь пакет DRAFT, 15 плейсхолдеров, журнал подписей пуст). **G0 (новый блокер): мемо об обезличивании описывает несуществующую конструкцию — юристу НЕ отдавать, пока код и мемо не сойдутся.**
- **Срок:** практика чтения counsel **2–4 недели** + 1–2 недели правок — **разработкой не сокращается** (legal).
- **Что сломается без T1:** нет правового основания сбора ПД (ФЗ-152) → нельзя пускать живых пользователей; ст.1253.1 щит посредника не включён (плейсхолдер abuse-контакта).

### T2 · ФЗ-152 РКН · residency
- **Источник:** legal + AUDIT4 residency-замок (FIXED-VERIFIED в конфиге). Уведомление/учёт РКН, подтверждение зоны РФ.
- **Срок:** уведомление РКН — календарное после T0; residency-конфиг = код (L-ФУНК, готов).

### T3 · Репутация G1–G4 — гейтит ТОЛЬКО включение reputation_reviews (не разработку)
- **Источник:** legal-мемо ФЗ-152. G1 согласие REVIEW_PUBLICATION (сейчас нет в union + нет эндпоинта), G2 модерация+спор live, G3 body-drop на erase, **G4 counsel-заключение по теории обезличивания — 2–6 недель, САМЫЙ ДЛИННЫЙ полюс, кодом не сокращается вовсе**.
- **Что сломается без T3:** нельзя ВКЛЮЧИТЬ отзывы для живых людей (форма F0 спит легально сколько угодно).

### T4 · Ветеринарный периметр livestock (Меркурий/ВетИС · 498-ФЗ · CITES)
- **Источник:** legal — рынок скота сейчас не загорожен юридически ничем. Перед ПЕРВЫМ живым листингом скота.
- **Срок:** календарный (интеграция ВетИС + предупреждение в форму); гейтит выход livestock-рынка, не pet.

### T5 · Платежи · 54-ФЗ · налог — последним, перед деньгами
- **Источник:** finance/legal. Касса, 115-ФЗ, режим налога продавца. amount_minor резерв (0 путей записи).
- **Что сломается без T5:** нельзя принимать деньги; но win-win/soft-start = ликвидность ПЕРВОЙ, деньги вторыми (владельческий канон) → T5 сознательно поздний.

### T6 · ⭐ ПРАВОВАЯ РАМКА АГЕНТА-ОПЕРАТОРА — самый глубокий временной неизвестный (Северная звезда)
- **Источник:** legal (ст.16 ФЗ-152 автоматизированное решение; ст.1253.1 — массовая автооценка читается как редакционный отбор → посредник перестаёт быть посредником) + security F3.
- **Суть:** мир НЕ ГОТОВ к ИИ-агенту как стороне соглашения — правосубъектность, подпись, ответственность, доверие контрагента. Это НЕ код и НЕ наш counsel — это темп развития права и практики.
- **Что даёт стратегии:** F3 (агент-власть) строим формой СЕЙЧАС; включение агента для ЖИВЫХ операторских решений — за T6, и T6 может отставать от всего на месяцы-годы. **Поэтому trust root = HUMAN навсегда (ADR-0036) — не ограничение, а мост через незрелость мира.**
- **ПРИНЦИП ЕДИНСТВЕННОГО ЧЕЛОВЕЧЕСКОГО УЗЛА (перспектива помощника, сильная):** мир не готов к агенту-стороне
  (правосубъектности нет и в горизонте лет [гипотеза]; УКЭП привязана к лицу, «подпись агенту» = передача ключа,
  регламентами запрещена [проверить]; МЧД/доверенности — для людей, не для ИИ). Рабочий паттерн, уже видимый в
  мире: **human-in-the-loop РОВНО НА ПОДПИСИ** — агент готовит всё, человек жмёт одну кнопку. Проектная директива
  для F3/архитектуры: строить процессы так, чтобы **точка подписи была ЕДИНСТВЕННЫМ человеческим узлом**. Тогда
  агентизация ВСЕГО остального не ждёт правовой эволюции мира, а когда мир дозреет (T6) — узел просто снимается,
  без переписывания. Это превращает trust-root=HUMAN из «моста» в **архитектурный шов**: один именованный
  человеческий узел, а не человек, размазанный по процессу. (serves→ North Star напрямую.)
- **Опасность витрины:** «у нас решает ИИ» само притягивает регуляторное внимание (маркировка ИИ-контента,
  ввод в заблуждение) [гипотеза]. Вывод: **агентность ВНУТРИ, человек — в подписи И в витрине.**

## 3. КАРТА ЗАВИСИМОСТЕЙ (рёбра графа: что чего ждёт)

```
L-ФУНК (недели, пилим вперёд, рубильник off):
  F0 схема ──▶ F1 деплой-блокеры ──▶ F2 наблюдаемость/откат ──▶ F3 агент-власть(форма)
  (все достижимы БЕЗ L-ВРЕМЯ; финиш = «функционально готово, рубильники off»)

L-ВРЕМЯ (месяцы, календарь+подпись, старт СЕЙЧАС параллельно):
  T0 юрлицо(3 р.д.) ──▶ T1 оферта(counsel 2-4 нед) ──▶ T2 РКН
                    └──▶ T5 платежи(поздно, soft-start)
  T0 ──▶ T3 репутация G1-G4 (G4 counsel 2-6 нед) ═══ гейтит рубильник reputation_reviews
  T0 ──▶ T4 ветеринария ═══ гейтит рубильник livestock-рынка
  T6 агент-правосубъектность (мир, годы?) ═══ гейтит ВКЛЮЧЕНИЕ агента-оператора живьём

РУБИЛЬНИКИ (где линии сходятся):
  выход pet-рынка = F0-F2 готовы ∧ T0∧T1∧T2
  включение отзывов = F0 готова ∧ T3(G1-G4)
  выход livestock = F1e ∧ T4
  приём денег = F-платёж ∧ T5
  агент-оператор живьём = F3 ∧ T6
```

## 4. РАЗВИЛКИ (не прячем — стоят в плане с ценой)
- **Дата T0 (юрлицо):** рано (L-ВРЕМЯ стартует раньше, взносы ×6 тикают) vs поздно (взносы позже, L-ВРЕМЯ сдвигается). Рек.: синхронно с «F близка к готова + оферта у counsel».
- **F1e объём сообщений:** минимальный человеческий слой (кличка+причина текстом) сейчас vs полный deep-link/read_at/категории. Рек.: минимальный человеческий слой в F1 (дёшево, снимает «нельзя показать»), богатый UX — с фронт-фазой.
- **F3 базовая роль агента:** провижинить агентов от USER/MODERATOR (least-privilege реален) vs ADMIN (наследует manage:all). Рек.: НИКОГДА ADMIN (security).

## 6. КАРТА ТАКТОВ временнОй линии + её ПЕРВЫЙ СПРИНТ (интегрировано из помощника; факты = гипотезы)

Помощник дал форму, которой не хватало: **считать L-ВРЕМЯ не списком процессов, а КАРТОЙ ТАКТОВ** — у
каждого оформления свой наименьший неделимый такт, и критический путь считается по тактам, а не по ощущению.

**Такты (гипотезы помощника — проверить первоисточником/world-monitor перед опорой):**

| Публикация оферты (юр.сила с акцепта) | мгновенно технически | но «правовой долг» фиксируется первыми акцептами |

**Первый спринт L-ВРЕМЯ (что оформляется ПАРАЛЛЕЛЬНО коду уже при НУЛЕВОМ продукте):** каркас оферты →

ролей). Вывод: у временнОй линии есть свой «первый спринт», и он стартует НЕ после кода, а сейчас.
